🛠️ PROBLEM SOLVING TECHNIQUES · UNIT II

Structured programming

Structured programming uses three simple shapes: do steps in order, choose a path, or repeat a block. This unit shows how those shapes become safe conditions and loops in C.

PICTURE IT

A program can go straight ahead, choose a path, or repeat a step. That is sequence, selection and repetition.

A route can go straight, choose left or right at a sign, or repeat a lap until the timer rings. Programs use the same three patterns.

BY THE END, YOU CAN

  • Recognize sequence, selection and repetition.
  • Choose if/else, switch, while or do-while for a task.
  • Trace loop conditions, updates and sentinel-controlled input.

01

The three control structures

Sequence executes statements in order. Selection chooses between paths based on a condition. Repetition runs a block multiple times while a rule holds. Most structured programs are built by combining these three patterns, which makes the logic easier to read and trace than arbitrary jumps.

Simple example

Read a mark (sequence), choose pass/fail (selection), repeat for each student (repetition).

Exam takeawayIdentify the control structure and explain its role in the algorithm.
02

if/else and switch

Use if/else when a condition such as mark>=40 selects between outcomes; conditions can be combined or nested. Use switch for a discrete choice among fixed values such as menu options. In C, each switch case generally needs a break to avoid falling through to the next case; include a default branch for unlisted values.

Simple example

A menu can switch on choice 1, 2 or 3 and display a message for default.

Exam takeawayShow the condition or cases, all outcomes and the fallback behavior.
03

while and do-while loops

A while loop is entry-controlled: its condition is checked before the body, so it may run zero times. A do-while loop is exit-controlled: its body runs once before the condition is checked, so it runs at least once. Choose while when work may not be needed; choose do-while for a menu that must appear once.

Simple example

Read values while input is available with while; show a menu at least once with do-while.

Exam takeawayState when each condition is checked and the minimum body count.
04

Loop initialization, condition and update

A safe loop has an initial state, a condition that controls repetition, a body and an update that moves toward termination. Trace the condition before and after each pass. A wrong boundary can skip an item or run one extra time; a missing update can create an infinite loop.

Simple example

For i=1; i<=n; i++, values 1 through n are included exactly once.

Exam takeawayShow the initial value, loop condition, update and stopping value.
05

Sentinel-controlled input and C translation

A sentinel is a special value that ends data entry and is not part of the data. The program must read a value before testing it and avoid adding the sentinel to totals. Translate pseudocode into C in small pieces, then trace zero, one and boundary inputs. Choose a sentinel that cannot be confused with valid data, or use a separate end marker.

Simple example

Read x; while x!=-1, add x to sum, read the next x; stop when -1 arrives.

Exam takeawayExplain sentinel handling, initialization, update and why it is excluded.
06

Sequence, selection and repetition

Sequence executes steps in order. Selection chooses among paths based on a condition. Repetition performs a block again while a rule holds. These three structures form the basis of structured programming. A clear program keeps each block focused and avoids jumps that make the path difficult to follow.

Simple example

Read a score, select pass or fail, then repeat the same process for each student.

Exam takeawayIdentify the structure used and state how control moves through it.
07

if/else versus switch

Use if/else for ranges, compound conditions or comparisons. Use switch when one expression is compared with several discrete constant cases. In C, each switch case usually needs break to prevent control from falling through to the next case; default handles values not listed. Choose the form that makes the decision clearest.

Simple example

A numeric menu choice 1–4 suits switch; a score >= 40 suits if/else.

Exam takeawayState whether the cases are exact values or broader conditions.
08

while and do-while loops

A while loop checks its condition before executing the body, so it can run zero times. A do-while loop checks after the body and therefore runs at least once. In C, the do-while ends with a semicolon. Choose based on whether the task must happen once before the condition can be checked.

Simple example

A menu should usually display once, so a do-while loop can be a natural fit.

Exam takeawayDraw the condition check position and say whether zero iterations are possible.
09

Sentinels and loop safety

A sentinel is a special input that signals the end of a sequence. It should not be treated as ordinary data, and it must be distinct from valid values. Initialize variables before the loop, read input at the right point, and ensure every pass updates state. These checks prevent off-by-one errors and accidental infinite loops.

Simple example

Read temperatures until −999 appears; update the average only for values other than −999.

Exam takeawayExplain why the sentinel cannot be confused with valid input and where it is checked.
10

Nested loops and execution tables

A nested loop completes the inner loop for each outer-loop value. Trace both indexes in a table; this reveals how many iterations occur and helps reason about patterns or matrix traversal. If both loops run n times, the total number of inner operations is approximately n². Boundary conditions must prevent index n from being accessed.

Simple example

For i=0..1 and j=0..2, the pairs are (0,0),(0,1),(0,2),(1,0),(1,1),(1,2).

Exam takeawayList the index pairs and show when each loop increments.
11

C operators, precedence and conditions

C evaluates operators according to precedence, and parentheses make the intended grouping explicit. Relational operators produce truth values; logical AND and OR combine conditions, while bitwise operators work on bits. Confusing = with == or using && instead of & changes behavior. Break complex conditions into named steps when tracing them.

Simple example

Use (marks >= 40 && attendance >= 75) for two conditions that must both hold.

Exam takeawayAdd parentheses and explain the condition in ordinary words.
12

Input validation and safe data handling

Input validation checks that a value is in the permitted range and in the expected form before it is used. Invalid input should be rejected, requested again or handled according to the specification. In C, also check whether input conversion succeeded when the problem requires robust handling. Validation prevents invalid values from corrupting later calculations.

Simple example

A menu accepting choices 1–4 should reject 0 and 5 before using the choice in a switch.

Exam takeawayState the valid range and describe what happens when input is outside it.
13

Loop tracing and off-by-one errors

Off-by-one errors happen when a loop runs one time too many or too few. Check the initial value, comparison operator and update as a set. For an array of n elements indexed 0 through n−1, a loop usually uses i<n; i<=n reaches an invalid index. Trace n=0, n=1 and a normal case.

Simple example

for(i=0;i<5;i++) visits 0,1,2,3,4 exactly five times.

Exam takeawayWrite the first and last loop values and count how many iterations occur.
14

Sequence, selection and iteration

Structured programming uses sequence (steps in order), selection (choose a branch) and iteration (repeat while a condition holds). Combining these constructs can express many algorithms without uncontrolled jumps. Each branch should cover the intended cases, and each loop needs an update that can eventually make its condition false.

Simple example

Read marks; if marks≥40 print pass, otherwise print retry; repeat this process for each student.

Exam takeawayLabel the control structure and verify every path and loop termination.
15

Conditions, comparisons and Boolean logic

A condition evaluates to true or false and controls a branch or loop. Relational operators compare values; logical AND, OR and NOT combine conditions. Parentheses make intended grouping explicit. Test boundary values because using > instead of ≥ changes whether the limit is included.

Simple example

age≥18 AND hasID is true only when both requirements are satisfied.

Exam takeawayTranslate the rule into a Boolean expression and test true and false cases.
16

Loop design and off-by-one errors

A loop has initialization, a condition and a progress update. A pre-test loop checks before each pass; a post-test loop runs at least once before checking. Off-by-one errors often come from mixing inclusive and exclusive endpoints. Trace the first and last iteration and make sure progress is guaranteed.

Simple example

For i=0 while i<n visits indices 0 through n−1, exactly n times when n≥0.

Exam takeawayState the initial value, condition, update and exact number of iterations.
17

Nested loops and pattern tracing

A nested loop runs an inner process for each outer iteration. Total work depends on how many times each loop executes; two loops of n iterations often create n² inner executions. Indentation and a trace table help keep the loop levels clear. Do not assume nested loops always have equal bounds.

Simple example

Rows r=1..3 and columns c=1..r print 1+2+3=6 symbols, not 3×3.

Exam takeawayList outer iterations and count inner steps for each one.
18

Pseudocode and flowchart conventions

Pseudocode expresses logic in readable, language-neutral steps. A flowchart represents process steps, decisions, input/output and direction with standard shapes and arrows. Both should show start and end, meaningful labels and all decision branches. They are plans to reason about, not decorations added after coding.

Simple example

A decision 'score ≥ 40?' must have both Yes and No paths leading to an output or later step.

Exam takeawayTrace every path from start to end and check that no branch is missing.
19

Modular design and structured testing

A modular program separates tasks into procedures or functions with clear contracts. Modules reduce repetition and make testing easier, but shared state and unclear interfaces create hidden dependencies. Test each module with expected inputs, then test that the modules work together as a system.

Simple example

A grade program can use separate functions for input validation, average calculation and grade selection.

Exam takeawayState each module's responsibility, inputs and outputs, then test units and integration.

How the unit fits together

Connect the definitions, methods and applications before you start memorizing.

Structured programming gives control flow three understandable forms. Sequence is the default order; selection splits execution according to a condition; repetition returns to a condition until stopping is appropriate. For every loop, describe an invariant that remains true and a progress measure that moves toward termination. A sentinel loop adds an input protocol: the program must distinguish valid data from the stop value. Translating pseudocode into C should preserve the logic first, then add syntax carefully. Boundary traces are especially valuable: zero repetitions, one repetition and the last value often expose off-by-one errors.

Sequence, selection and repetition

Sequence runs statements in order. Selection chooses a branch, commonly with if/else or switch. Repetition runs a block while a condition holds. Combining these structures produces programs that are easier to read and reason about.

02

A while loop tests before the body, so it may run zero times. A do-while loop tests after the body, so it runs at least once; it often suits a menu that must appear once. Every loop needs an initial state, a condition and an update that eventually makes the condition false.

03

Sentinels stop input safely

EXAMPLE 1

Trace a while loop for odd numbers

TaskDisplay odd numbers from 1 through 8 using i=1; while i<=n: print i; i+=2.

  1. Start i=1; 1<=8, so print 1 and update i=3.
  2. 3<=8: print 3, update i=5. Then print 5 and update i=7.
  3. 7<=8: print 7, update i=9.
  4. 9<=8 is false, so stop.
Answer and reason

Output is 1, 3, 5, 7. The loop condition excludes 9.

EXAMPLE 2

Read values until a sentinel

TaskSum nonnegative scores until −1 is entered.

  1. Initialize sum=0 and count=0; read x.
  2. While x!=-1, add x to sum, increase count and read the next value.
  3. Do not include −1 in either sum or count.
  4. Before average=sum/count, check count>0.
Answer and reason

The sentinel controls stopping but is not a data value; the count check prevents division by zero.

QUESTION 1Compare while and do-while loops.+

A while loop is entry-controlled: its condition is tested before each pass, so its body may run zero times. A do-while loop is exit-controlled: the body runs once before the condition is tested, so it runs at least once. Use while when the loop may not need to start, such as reading until an input is available. Use do-while for a menu that must be shown at least once.

QUESTION 2Write the logic for displaying odd numbers from 1 through n.+

Initialize i to 1. While i is less than or equal to n, display i and add 2 to i. The loop visits 1, 3, 5 and so on, so every displayed value is odd and no value exceeds n. If n is less than 1, the loop displays nothing. In C, the loop condition is i <= n and the update is i += 2.

WORK IT THROUGH

Display odd numbers from 1 through n.

  1. Set i=1. While i<=n, display i and add 2 to i.
  2. For n=6, the loop shows 1, 3 and 5. The next value is 7, so the condition is false.
  3. For n<1, the condition is false at the start and nothing is displayed; that is correct for this rule.

WATCH OUT FOR

Easy mix-ups

  • A while loop might run zero times; a do-while loop runs at least once.
  • If a loop variable never moves toward the stopping condition, it may never end.
  • Do not include a sentinel in a total or average.
