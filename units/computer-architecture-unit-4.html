Speed, I/O & memory

This unit explains how computers improve speed and communicate with devices. The central idea is balance: a processor is fast, while memory and devices may be slower, so computers use overlap, caches and transfer methods to avoid wasting time.

LESSON PATH

Build the idea step by step

Read one card, say it back in your own words, then try the example.

01

Pipelining overlaps work

A pipeline divides instruction work into stages such as fetch, decode and execute. While one instruction executes, another can be decoded and another fetched. This improves how many instructions finish over time; it does not remove the steps in each instruction. Data, control and resource hazards can force pauses, so real speedup is below the ideal.

02

Fast memory works because use has patterns

Registers, cache, main memory and storage form a hierarchy: smaller, faster levels sit near the CPU; larger, slower levels are farther away. Cache stores blocks likely to be used again. Temporal locality means recently used data may be needed again; spatial locality means nearby addresses may be used soon. Virtual memory maps a program's logical address space onto physical memory, with storage supporting the illusion of a larger space.

03

I/O can keep the CPU from waiting

With programmed I/O, the CPU repeatedly checks a device and transfers data. With interrupt-driven I/O, the device asks for attention. With DMA, a controller moves a block between a device and memory after CPU setup. Booth's multiplication algorithm handles signed binary multiplication by examining neighboring multiplier bits and choosing add, subtract or shift steps.

✦

WORK IT THROUGH

Compare three ways to receive a device update.

  1. Programmed I/O: the CPU keeps asking if the device is ready. This is simple but spends CPU time waiting.
  2. Interrupt: the device signals the CPU when it needs help. The CPU can do other work until then.
  3. DMA: for a large block, the CPU starts the transfer and the controller moves the data; the CPU is notified when it finishes.

WATCH OUT FOR

Easy mix-ups

  • Pipelining improves throughput; hazards can stall it.
  • A cache hit and a cache miss take different paths.
  • DMA still needs CPU setup; it reduces CPU work during transfer.

CORE IDEAS TO REMEMBER
01

A pipeline overlaps instruction stages. Ideal speedup is limited by hazards, unequal stage time and pipeline startup or drain.

02

Interrupt-driven I/O lets a device request attention; DMA transfers a block between device and memory with less CPU involvement.

03

Booth's algorithm handles signed binary multiplication by examining adjacent multiplier bits and applying add, subtract or shift operations.

04

Memory hierarchy places small, fast storage near the CPU and larger, slower storage farther away.

05

Cache exploits locality. Virtual memory gives processes a logical address space backed by physical memory and secondary storage.

IMPORTANT QUESTIONS · TAP TO REVEAL MODEL ANSWERS
QUESTION 1Explain cache memory and locality.+

Cache is a small, fast memory between the CPU and main memory. It stores recently or frequently used data and instructions. Temporal locality means recently used items may be used again; spatial locality means nearby addresses may be used soon. A cache hit supplies data quickly; a miss requires a slower lower-level access. Explain hit rate, blocks and replacement policy when the question asks for detail.

QUESTION 2Compare programmed I/O, interrupt-driven I/O and DMA.+

With programmed I/O, the CPU repeatedly checks device status and transfers data. Interrupt-driven I/O lets the device signal the CPU when it needs service, reducing busy waiting. DMA uses a controller to move a block between a device and memory; the CPU sets up the transfer and is notified when it completes. DMA is efficient for larger transfers, while interrupts suit events needing CPU attention.
