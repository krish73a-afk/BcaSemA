🧩 COMPUTER ARCHITECTURE · UNIT IV

Speed, I/O & memory

This unit explains how computers improve speed and communicate with devices. The central idea is balance: a processor is fast, while memory and devices may be slower, so computers use overlap, caches and transfer methods to avoid wasting time.

01

Instruction pipelining

Pipelining divides instruction work into stages and overlaps different instructions in those stages. Once the pipeline is full, several instructions can make progress at once, improving throughput. It does not necessarily shorten the latency of one instruction. Ideal speedup assumes balanced stages and no interruptions; real pipelines lose time to startup, draining and hazards.

Simple example

While instruction 1 executes, instruction 2 can decode and instruction 3 can be fetched.

Exam takeawayExplain overlap, then distinguish throughput from the time for one instruction.
02

Pipeline hazards and stalls

A structural hazard occurs when two stages need the same hardware resource at once. A data hazard occurs when an instruction needs a value that an earlier instruction has not produced yet. A control hazard follows a branch whose next address is not yet known. The processor may stall, forward a value or predict a branch; these measures reduce but do not erase the cost.

Simple example

If an instruction adds R1 and the next instruction immediately uses the new R1, the second may need to wait or receive a forwarded result.

Exam takeawayName the hazard, show the dependency or conflict and describe its effect on the pipeline.
03

Memory hierarchy and locality

Storage is arranged in levels: registers and cache are small and fast; main memory is larger but slower; secondary storage is much larger and slower again. This hierarchy balances speed and capacity. It works well because programs show locality: temporal locality means recent items may be reused, while spatial locality means nearby addresses may be accessed soon.

Simple example

A loop repeatedly using the same array section may benefit from both temporal and spatial locality.

Exam takeawayDraw the levels in order and explain why size, speed and cost change across them.
04

Cache, hits and misses

A cache keeps copies of blocks from main memory near the CPU. On a hit, the needed block is already in cache; on a miss, it must be fetched from a slower level. The hit rate is hits divided by total accesses. Cache blocks exploit locality; when space is full, a replacement rule selects a block to remove. More cache can help, but its design and access patterns matter.

Simple example

If 90 of 100 requests hit in cache, the hit rate is 90%.

Exam takeawayDefine cache, hit, miss and hit rate; connect performance to locality.
05

Programmed I/O, interrupts and DMA

With programmed I/O, the CPU repeatedly checks device status and moves data itself, which can waste time waiting. Interrupt-driven I/O lets a device signal when service is needed. Direct Memory Access (DMA) uses a controller to move a block between a device and memory after the CPU sets up the transfer. The CPU is notified when the block is done, making DMA useful for larger transfers.

Simple example

A disk can signal an interrupt when ready; for a large file block, DMA can transfer data while the CPU does other work.

Exam takeawayCompare who checks, who moves the data and how much CPU time is occupied.
06

Booth's signed multiplication

Booth's algorithm multiplies signed binary numbers represented in two's complement. It examines the current multiplier bit together with the previous bit: 01 indicates add the multiplicand, 10 indicates subtract it, and 00 or 11 means no add/subtract. After the operation, an arithmetic right shift preserves the sign. Repeat for the required number of bits. Keep the register layout and sign extension consistent.

Simple example

For each multiplier-bit pair, write the add/subtract/no-op decision before shifting; this prevents losing the sign.

Exam takeawayShow the initial registers, bit-pair decision, arithmetic shift and final product.
07

Pipeline stages and ideal speedup

Pipelining divides instruction work into stages that operate on different instructions at the same time. The first result still waits for the pipeline to fill, but after that an ideal pipeline can complete roughly one instruction per clock. For k stages and n instructions, ideal cycles are k+n−1, assuming equal stage time and no hazards. It improves throughput more directly than the latency of one instruction.

Simple example

A 4-stage ideal pipeline running 6 instructions takes 4+6−1=9 cycles, rather than 24 stage-times without overlap.

Exam takeawayWrite the ideal assumptions before calculating cycles or speedup.
08

Data, control and structural hazards

A data hazard occurs when an instruction needs a value that an earlier instruction has not finished producing. A control hazard occurs when a branch makes the next instruction uncertain. A structural hazard occurs when two operations need the same hardware resource at once. A processor may wait, forward a value, duplicate a resource or predict a branch. Name the hazard and explain why the next work cannot safely proceed.

Simple example

If instruction 2 uses R1 written by instruction 1, it may need forwarding or a stall.

Exam takeawayIdentify the dependency first, then describe the remedy and any cost.
09

Cache mapping and replacement

A cache holds copies of memory blocks. Direct mapping assigns each block to one cache line; fully associative mapping allows a block in any line; set-associative mapping allows a block in one set. A tag identifies which memory block is present. When a set is full, a replacement policy chooses a line to evict. The mapping choice trades hardware complexity, speed and conflict misses.

Simple example

With four direct-mapped lines, block numbers 0, 4 and 8 all map to line 0 if the line index is block number modulo 4.

Exam takeawaySeparate the block number, line or set index, and tag when solving a mapping question.
10

Interrupt I/O and DMA transfer

Programmed I/O makes the CPU repeatedly check a device. Interrupt-driven I/O lets the device request attention when ready, so the CPU can do other work meanwhile. Direct memory access (DMA) transfers a block between a device and memory after the CPU sets up address, direction and length; an interrupt can report completion. DMA is especially useful for larger transfers, though setup and coordination still take time.

Simple example

For a disk block, the CPU configures DMA once, continues another task, then handles the completion interrupt.

Exam takeawayCompare who moves each data item and when the CPU is interrupted.
11

Virtual memory and address translation

Virtual memory gives each process a logical address space that the operating system maps to physical memory. Paging divides virtual and physical memory into pages and frames; a page table records the mapping. A page fault occurs when the needed page is not currently in RAM, so the OS fetches it from secondary storage. This supports protection and larger address spaces, but storage access is slower.

Simple example

A virtual page number plus offset is translated to a frame number plus the same offset.

Exam takeawayExplain page, frame, page table and page fault in the order they are used.
12

Cache write-through and write-back

With write-through, a cache update is also sent to main memory, keeping the two copies synchronized but increasing traffic. With write-back, the cache marks a changed block dirty and writes it to memory only when it is evicted. Write-back can reduce traffic but needs extra state and careful handling. A question may also specify write-allocate or no-write-allocate on a miss.

Simple example

A dirty write-back block is copied to memory when its cache line must be replaced.

Exam takeawayState when memory is updated and what extra behavior the policy requires.
13

Throughput, latency and pipeline speedup

Latency is the time for one instruction or task to finish; throughput is how many finish per unit time. Pipelining mainly raises throughput by overlapping stages, while the first result still waits for the pipeline to fill. Ideal speedup is bounded by stage balance and stage count; stalls, branches and unequal stage delays lower the real gain.

Simple example

A five-stage pipeline may approach one completion per cycle after filling, even though one instruction still visits five stages.

Exam takeawayUse the word throughput for overlap and latency for one task's elapsed time.
14

Booth multiplication: bit-pair decision table

Booth's algorithm represents signed two's-complement multiplication compactly. Inspect the current low multiplier bit Q₀ and the extra bit Q₋₁: 00 or 11 means no add/subtract, 01 means add the multiplicand, and 10 means subtract it. Then perform an arithmetic right shift of the combined registers and repeat for the chosen bit width.

Simple example

For the pair Q₀Q₋₁=10, subtract M before the arithmetic shift.

Exam takeawayWrite each pair decision and show the A, Q and Q₋₁ registers after every shift.
15

Temporal and spatial locality in real programs

Temporal locality means recently accessed data or instructions are likely to be used again. Spatial locality means addresses near a recent access are likely to be used soon. Sequential array traversal has strong spatial locality; repeatedly using a loop counter has temporal locality. Caches exploit these patterns by transferring blocks rather than isolated bytes.

Simple example

Reading array[0], array[1], array[2] uses nearby memory and demonstrates spatial locality.

Exam takeawayGive a program example and state which kind of locality it shows.
16

Cache hit rate, miss rate and miss penalty

A hit occurs when the requested block is already in cache; a miss requires a lower memory level. Hit rate plus miss rate equals 1. Average access time depends on hit time and the extra miss penalty. Clarify whether the problem's miss time includes the initial cache lookup before substituting values into a formula.

Simple example

A 96% hit rate means a 4% miss rate; a long miss penalty can still dominate average time.

Exam takeawayWrite the formula and define each timing term before calculating.
17

Pipeline forwarding and stalls

Forwarding sends a newly computed value directly from a later pipeline stage to a dependent instruction, avoiding a wait for register write-back. A stall inserts a bubble when a value or resource is not ready. Forwarding cannot solve every dependency, especially when a load result arrives too late; a short stall may still be required.

Simple example

An ADD result can be forwarded to the next instruction's ALU input instead of waiting for register write-back.

Exam takeawayShow the producer, consumer and stage where the value becomes available.
18

Page faults and working sets

A page fault occurs when a process accesses a virtual page that is not currently resident in physical memory. The operating system selects a frame, may evict another page, loads the needed page and updates the page table. If a program repeatedly faults because its active pages do not fit, performance can collapse; this is why locality and working-set size matter.

Simple example

A loop over a large array may fault repeatedly if its active pages exceed available frames.

Exam takeawayTrace fault → replacement decision → page load → page-table update.
19

DMA setup and completion sequence

For DMA, the CPU provides a starting address, transfer direction and length to the controller. The controller requests access to the bus and moves a block between device and memory. When complete, it can interrupt the CPU. Exact bus arbitration varies, but DMA does not mean the CPU is absent from setup or error handling.

Simple example

The CPU configures a 4 KB disk transfer, then receives one completion interrupt instead of moving every byte itself.

Exam takeawayState the CPU's setup role, controller's transfer role and completion signal.
20

Booth algorithm arithmetic shift

In Booth multiplication, the combined accumulator A, multiplier Q and extra bit Q₋₁ are shifted as one signed value. The shift is arithmetic: it preserves A's sign bit while moving bits right. Repeat once per chosen operand bit. Using the wrong shift or bit width can corrupt negative products, so show the register contents after every iteration.

Simple example

For an 8-bit signed calculation, keep A and Q at the specified width throughout all iterations.

Exam takeawayLabel A, Q and Q₋₁ before and after each arithmetic right shift.

How the unit fits together

Connect the definitions, methods and applications before you start memorizing.

Performance depends on keeping work moving while respecting dependencies. A pipeline overlaps stages, but a dependency may force a wait: an instruction cannot use a result that has not been produced, a branch can make the next instruction uncertain, and two stages may need the same hardware. Memory hierarchy uses locality to reduce average waiting time. A cache does not store every memory location; it keeps blocks likely to be reused, and a miss sends the request to a slower level. I/O methods decide how much the CPU participates in data movement. Programmed I/O is simple but can waste processor cycles; interrupts notify the CPU when needed; DMA is suited to blocks. Booth multiplication is a separate arithmetic procedure for signed two's-complement values and should be shown as a sequence of bit decisions and arithmetic shifts.

Quick recap: teach these links back

01

Pipelining overlaps work

A pipeline divides instruction work into stages such as fetch, decode and execute. While one instruction executes, another can be decoded and another fetched. This improves how many instructions finish over time; it does not remove the steps in each instruction. Data, control and resource hazards can force pauses, so real speedup is below the ideal.

02

Fast memory works because use has patterns

Registers, cache, main memory and storage form a hierarchy: smaller, faster levels sit near the CPU; larger, slower levels are farther away. Cache stores blocks likely to be used again. Temporal locality means recently used data may be needed again; spatial locality means nearby addresses may be used soon. Virtual memory maps a program's logical address space onto physical memory, with storage supporting the illusion of a larger space.

03

I/O can keep the CPU from waiting

With programmed I/O, the CPU repeatedly checks a device and transfers data. With interrupt-driven I/O, the device asks for attention. With DMA, a controller moves a block between a device and memory after CPU setup. Booth's multiplication algorithm handles signed binary multiplication by examining neighboring multiplier bits and choosing add, subtract or shift steps.

EXAMPLE 1

Estimate ideal pipeline cycles

TaskAn ideal five-stage pipeline executes eight instructions. Ignore hazards and unequal stage delays.

  1. Without pipelining, each instruction uses all five stages before the next starts: 8×5=40 stage-times.
  2. With pipelining, the first instruction takes five stages to emerge, then one instruction completes each additional stage-time.
  3. Total ideal time is k+n−1=5+8−1=12 stage-times.
Answer and reason

Ideal speedup is 40/12≈3.33. Real hazards, startup and stage imbalance reduce it.

EXAMPLE 2

Calculate a simple cache average access time

TaskAssume a 1 ns cache hit, 50 ns memory miss service and a 95% hit rate. Use this simplified model.

  1. Hit probability is 0.95; miss probability is 1−0.95=0.05.
  2. Weighted time = 0.95×1 ns + 0.05×50 ns.
  3. That is 0.95 ns + 2.5 ns = 3.45 ns.
Answer and reason

The simplified average is 3.45 ns. Actual cache timing depends on whether miss service includes the initial cache lookup.

QUESTION 1Explain cache memory and locality.+

Cache is a small, fast memory between the CPU and main memory. It stores recently or frequently used data and instructions. Temporal locality means recently used items may be used again; spatial locality means nearby addresses may be used soon. A cache hit supplies data quickly; a miss requires a slower lower-level access. Explain hit rate, blocks and replacement policy when the question asks for detail.

QUESTION 2Compare programmed I/O, interrupt-driven I/O and DMA.+

With programmed I/O, the CPU repeatedly checks device status and transfers data. Interrupt-driven I/O lets the device signal the CPU when it needs service, reducing busy waiting. DMA uses a controller to move a block between a device and memory; the CPU sets up the transfer and is notified when it completes. DMA is efficient for larger transfers, while interrupts suit events needing CPU attention.

WORK IT THROUGH

Compare three ways to receive a device update.

  1. Programmed I/O: the CPU keeps asking if the device is ready. This is simple but spends CPU time waiting.
  2. Interrupt: the device signals the CPU when it needs help. The CPU can do other work until then.
  3. DMA: for a large block, the CPU starts the transfer and the controller moves the data; the CPU is notified when it finishes.

Easy mix-ups

  • Pipelining improves throughput; hazards can stall it.

Model answer  Cache is a small, fast memory between the CPU and main memory. It stores recently or frequently used data and instructions. Temporal locality means recently used items may be used again; spatial locality means nearby addresses may be used soon. A cache hit supplies data quickly; a miss requires a slower lower-level access. Explain hit rate, blocks and replacement policy when the question asks for detail.  Question: Compare programmed I/O, interrupt-driven I/O and DMA.  Model answer  With programmed I/O, the CPU repeatedly checks device status and transfers data. Interrupt-driven I/O lets the device signal the CPU when it needs service, reducing busy waiting. DMA uses a controller to move a block between a device and memory; the CPU sets up the transfer and is notified when it completes. DMA is efficient for larger transfers, while interrupts suit events needing CPU attention.
