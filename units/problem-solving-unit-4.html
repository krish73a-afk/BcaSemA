Functions, recursion & arrays

Functions, arrays and recursion help programs stay organized and solve repeated patterns. This unit connects reusable tasks with stored lists, searches, sorting and the discipline recursion needs to stop.

PICTURE IT

A function is a named helper. Recursion is when a helper asks a smaller version of itself for help.

A function is a named helper job. An array is a row of labelled boxes. Recursion asks the same helper to solve a smaller version until it reaches a simple base case.

BY THE END, YOU CAN

  • Distinguish a function prototype from its definition.
  • Use recursion with a base case and a step toward it.
  • Respect array bounds and the requirements of search and matrix addition.
✧

LESSON PATH

Build the idea step by step

Read one card, say it back in your own words, then try the example.

01

Functions give tasks a name

A function prototype tells the compiler the function's name, return type and parameters. A definition contains the body that performs the task. Functions split, reuse and clarify work. Choose parameters for information the helper needs and a return value for its result.

02

Recursion must move toward a base case

A recursive function calls itself on a smaller or simpler input. Its base case returns without another recursive call. For factorial, 0!=1 and n!=n×(n−1)! for n>0. Each call decreases n, so it reaches zero; without that progress, calls can exhaust the stack.

03

Arrays and algorithms have conditions

A C array of n items uses indexes 0 through n−1; an out-of-range index is an error. Binary search halves a sorted array, so it is not valid on unsorted values. Selection sort repeatedly places the smallest remaining value next. A two-dimensional array can represent a matrix; addition needs matching dimensions.

✦

WORK IT THROUGH

Trace factorial(4) recursively.

  1. factorial(4)=4×factorial(3); factorial(3)=3×factorial(2).
  2. Continue: factorial(2)=2×factorial(1); factorial(1)=1×factorial(0).
  3. factorial(0)=1, so work back up: 1, 1, 2, 6, 24. The base case stops the calls.

WATCH OUT FOR

Easy mix-ups

  • A recursive call must move closer to its base case.
  • Binary search requires sorted input.
  • For n array items, n is not a valid index; the last index is n−1.

CORE IDEAS TO REMEMBER
01

A function prototype declares its name, return type and parameters before use; a definition supplies the body.

02

A recursive function needs a base case and a step that moves toward it.

03

Arrays use zero-based indexes in C; for an array of n elements, valid indexes are 0 through n-1.

Binary search requires sorted data; selection sort repeatedly places the smallest remaining value.

05

IMPORTANT QUESTIONS · TAP TO REVEAL MODEL ANSWERS
QUESTION 1Explain recursion using factorial.+

Factorial follows n! = n x (n-1)! for n>0, with the base case 0!=1. A recursive function returns 1 when n is 0; otherwise it returns n multiplied by factorial(n-1). The argument decreases on every call, so it eventually reaches zero. Without a correct base case, calls continue until the program exhausts its call stack.

QUESTION 2When may binary search be used, and what is its main idea?+

Binary search requires the array to be sorted. Compare the target with the middle element. If they match, stop. If the target is smaller, continue in the left half; if larger, continue in the right half. Repeat until found or the search interval is empty. Each comparison roughly halves the remaining interval, so its time grows logarithmically with the number of elements. It is not valid on unsorted input.
