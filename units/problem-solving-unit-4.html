Functions, recursion & arrays

Functions, arrays and recursion help programs stay organized and solve repeated patterns. This unit connects reusable tasks with stored lists, searches, sorting and the discipline recursion needs to stop.

PICTURE IT

A function is a named helper. Recursion is when a helper asks a smaller version of itself for help.

A function is a named helper job. An array is a row of labelled boxes. Recursion asks the same helper to solve a smaller version until it reaches a simple base case.

01

Function prototypes, definitions and calls

A function prototype declares a function's name, return type and parameter types before it is used. A definition provides the body. A call passes arguments and may receive a return value. Functions divide a solution into focused tasks and allow reuse. Parameters and return types should match between declaration, definition and call.

Simple example

int square(int n); declares the function; its definition returns n*n; square(4) returns 16.

Exam takeawayIdentify prototype, definition, arguments, parameters and returned value.
02

Recursion and base cases

A recursive function calls itself with a smaller or simpler input. It needs a base case that returns without another recursive call and a recursive step that moves toward that base. Every call uses stack space, so failure to progress can cause unbounded calls and stack exhaustion. Trace calls down, then values back up.

Simple example

factorial(n)=1 for n=0; otherwise n×factorial(n−1).

Exam takeawayName the base case and prove each call approaches it.
03

Arrays and valid indexes

An array stores several values of one type in contiguous indexed positions. In C, indexing starts at 0, so an array of n items has valid indexes 0 through n−1. A loop should stop before n. Reading beyond the bounds is undefined behavior and can corrupt results; keep the length alongside the array.

Simple example

For int a[5], valid elements are a[0] through a[4].

Exam takeawayState the index range and show a loop condition such as i<n.
04

Searching and sorting

Binary search compares a target with the middle of a sorted array and discards the half that cannot contain it. Each step roughly halves the search range, giving logarithmic growth in comparisons. It is not valid on unsorted data. Selection sort repeatedly finds the smallest remaining item and places it next in the sorted prefix; it is simple but uses many comparisons.

Simple example

Search [2,5,8,12,16] for 12: compare 8, keep the right half, then find 12.

Exam takeawayState binary search's sorted-input requirement and show interval updates.
05

Two-dimensional arrays and matrix addition

A two-dimensional array uses a row and column index to represent a table or matrix. Nested loops visit each position. Matrix addition is defined for matrices with matching dimensions; add entries at the same row and column. Keep loop limits aligned with row and column counts and print a line break after each output row.

Simple example

For A=[[1,2],[3,4]] and B=[[5,6],[7,8]], A+B=[[6,8],[10,12]].

Exam takeawayCheck dimensions, use nested loops and show corresponding-entry addition.
06

Function scope and parameter passing

A function prototype tells the compiler the function name, return type and parameter types. The definition contains the implementation, and a call supplies arguments. In C, ordinary arguments are passed by value, so changing a parameter does not change the caller's variable. A pointer can be passed when a function must modify data owned by the caller.

Simple example

void addOne(int x) changes only its local copy; addOne(&x) needs a pointer parameter to update the original.

Exam takeawayDistinguish a local parameter value from the caller's variable.
07

Recursion trace and call stack

Each recursive call gets its own parameters and local state on the call stack. Trace calls downward until the base case, then trace returned values upward. A valid recursive step must make progress toward the base case. Deep recursion can use substantial stack space, so iteration may be safer for large inputs.

Simple example

factorial(3) calls factorial(2), then factorial(1), then factorial(0)=1 before returning 1, 2 and 6.

Exam takeawayShow both the stopping case and how each call returns its result.
08

Array bounds and linear search

For an array with n elements in C, valid indexes are 0 through n−1. Linear search checks items one by one and works even when values are unsorted. It can stop at the first match or inspect the full array if all matches are needed. Never access index n, and handle an empty array before reading element zero.

Simple example

In a 5-item array, indexes 0,1,2,3,4 are valid; index 5 is outside the array.

Exam takeawayState the array length and use a loop condition i<n.
09

Selection sort and matrix dimensions

Selection sort repeatedly finds the smallest remaining item and swaps it into the next position; its nested comparisons make it O(n²) in typical analysis. Matrix addition is performed element by element and is defined only when both matrices have the same number of rows and columns. Check dimensions before looping.

Simple example

Add [[1,2],[3,4]] and [[5,6],[7,8]] by adding corresponding cells to get [[6,8],[10,12]].

Exam takeawayExplain the invariant or matching-position rule and verify the dimensions.

How the unit fits together

Connect the definitions, methods and applications before you start memorizing.

Functions create boundaries around tasks. A prototype tells the compiler how a function can be called; the definition implements it. Arrays organize many values under one name, but C does not check an index for you, so length and bounds are part of the algorithm's correctness. Recursion uses the call stack to remember unfinished work; every call must move toward a base case. Searching and sorting add preconditions: binary search relies on order, while selection sort gradually builds a sorted prefix. Two-dimensional arrays represent rows and columns, and operations such as addition require matching shapes. These ideas fit together: decompose a problem into functions, pass arrays and dimensions explicitly, and test boundaries.

Quick recap: teach these links back

01

Functions give tasks a name

A function prototype tells the compiler the function's name, return type and parameters. A definition contains the body that performs the task. Functions split, reuse and clarify work. Choose parameters for information the helper needs and a return value for its result.

02

Recursion must move toward a base case

A recursive function calls itself on a smaller or simpler input. Its base case returns without another recursive call. For factorial, 0!=1 and n!=n×(n−1)! for n>0. Each call decreases n, so it reaches zero; without that progress, calls can exhaust the stack.

03

Arrays and algorithms have conditions

A C array of n items uses indexes 0 through n−1; an out-of-range index is an error. Binary search halves a sorted array, so it is not valid on unsorted values. Selection sort repeatedly places the smallest remaining value next. A two-dimensional array can represent a matrix; addition needs matching dimensions.

Follow every step

Try each task yourself first, then compare your working with the explanation.

EXAMPLE 1

Trace factorial recursively

TaskEvaluate factorial(4), where 0!=1 and n!=n×(n−1)!.

  1. factorial(4)=4×factorial(3).
  2. factorial(3)=3×factorial(2); factorial(2)=2×factorial(1).
  3. factorial(1)=1×factorial(0). The base case factorial(0)=1 stops recursion.
  4. Return upward: 1, then 1, then 2, then 6, then 24.
Answer and reason

4!=24. The base case and decreasing argument guarantee termination for n≥0.

EXAMPLE 2

Trace binary search

TaskSearch sorted [2,5,8,12,16,20,24] for 20.

  1. Use low=0, high=6; mid=floor((0+6)/2)=3, value 12.
  2. 20>12, so discard indexes 0 through 3; set low=4.
  3. mid=floor((4+6)/2)=5, value 20; target found at index 5.
  4. If low ever exceeds high, report not found.
Answer and reason

Binary search works because the array is sorted, so each comparison eliminates half.

QUESTION 1Explain recursion using factorial.+

Factorial follows n! = n x (n-1)! for n>0, with the base case 0!=1. A recursive function returns 1 when n is 0; otherwise it returns n multiplied by factorial(n-1). The argument decreases on every call, so it eventually reaches zero. Without a correct base case, calls continue until the program exhausts its call stack.

QUESTION 2When may binary search be used, and what is its main idea?+

Binary search requires the array to be sorted. Compare the target with the middle element. If they match, stop. If the target is smaller, continue in the left half; if larger, continue in the right half. Repeat until found or the search interval is empty. Each comparison roughly halves the remaining interval, so its time grows logarithmically with the number of elements. It is not valid on unsorted input.

WORK IT THROUGH

Trace factorial(4) recursively.

  1. factorial(4)=4×factorial(3); factorial(3)=3×factorial(2).
  2. Continue: factorial(2)=2×factorial(1); factorial(1)=1×factorial(0).
  3. factorial(0)=1, so work back up: 1, 1, 2, 6, 24. The base case stops the calls.
