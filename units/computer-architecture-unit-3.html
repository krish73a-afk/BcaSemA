🧩 COMPUTER ARCHITECTURE · UNIT III

CPU & instructions

A processor is a team of small parts that move and transform data. This unit follows one instruction through that team and explains the registers, addressing choices and stack that make the work orderly.

PICTURE IT

The CPU follows a recipe: find an instruction, understand it, do it, then move to the next one.

Think of the CPU as a cook following a recipe. The program counter points to the next step, the instruction register holds it, and the ALU does arithmetic or logic.

01

CPU registers

Registers provide very fast working storage inside the processor. The program counter (PC) holds the address used for the next instruction fetch. The instruction register (IR) holds the instruction being decoded or executed. The memory address register (MAR) identifies a memory location; the memory data register (MDR) carries data moving to or from memory. An accumulator or general-purpose register holds operands and results.

Simple example

To read memory location 120, the CPU can place 120 in the MAR and receive the fetched value through the MDR.

Exam takeawayName each register and describe the information it carries, not just its abbreviation.
02

Fetch, decode, execute and write-back

The PC supplies an instruction address. During fetch, the instruction is read into the IR and the PC advances. During decode, the control unit identifies the operation, operands and addressing method. During execute, the ALU, memory or a device performs the operation. The result is written to a register or memory. A branch can replace the normal next PC value; an interrupt can temporarily transfer control elsewhere.

Simple example

For ADD R1,R2, fetch the instruction, decode the register names, add their values in the ALU, then store the result.

Exam takeawayWrite the stages in order and connect each one to the relevant register or unit.
03

Addressing modes locate operands

An addressing mode tells the CPU where an instruction's operand comes from. Immediate addressing includes the value in the instruction. Direct addressing gives the operand's memory address. Indirect addressing points to a location that contains the actual address. Register addressing names a CPU register. The same operation can use different modes, changing where the processor obtains its data.

Simple example

ADD #5,R1 uses an immediate value 5; ADD R2,R1 uses the value held in R2.

Exam takeawayFor each mode, say whether the instruction contains a value, address, pointer or register name.
04

RISC and CISC design tendencies

RISC traditionally favors a smaller set of simpler, regular instructions, which can make decoding and pipelining more predictable. CISC traditionally offers a larger set of more complex instructions, sometimes combining several operations. These describe design tendencies rather than strict modern categories: processors may translate complex instructions into simpler internal operations. Compare instruction style and tradeoffs without claiming one label means every CPU behaves identically.

Simple example

A RISC-style instruction may load a value, then use a separate add; a CISC-style instruction may combine more work in one instruction.

Exam takeawayCompare instruction complexity, format and implementation tendency; mention that real designs can blend ideas.
05

Stack organization

A stack is last-in, first-out (LIFO) storage: the most recently pushed item is the first popped. A stack pointer identifies the current top. CPUs use stacks for return addresses, temporary values, saved registers and function parameters. A function call can save where to return, do its work and restore that address when it finishes.

Simple example

Push A, then B; the next pop returns B before A.

Exam takeawayDefine LIFO and connect the stack pointer to calls or temporary storage.
06

CPU buses and the datapath

A datapath moves values among registers, the arithmetic-logic unit and memory interfaces. Address, data and control signals have different jobs: an address selects a location, data carries a value, and control signals specify actions such as read or write. A shared bus saves wiring but only one source may drive it at a time. Tracing a data movement diagram helps explain how an instruction is carried out.

Simple example

A memory read places an address in MAR, asserts a read control signal, then receives data in MDR.

Exam takeawayIdentify the source, destination and control action for each transfer.
07

Instruction fields: opcode and operands

A machine instruction is encoded as bits. The opcode identifies the operation, while operand fields identify registers, values or addresses. Some instructions include addressing-mode bits or an immediate constant. Instruction length and field sizes constrain how many operations, registers or addresses can be represented. Decode a small instruction by labelling each field before describing its effect.

Simple example

In a simple format [opcode | destination | source], ADD | R1 | R2 means add the source value into the destination register.

Exam takeawaySeparate what operation is requested from where its operands are found.
08

Immediate, direct, indirect and register addressing

Addressing modes describe how an instruction reaches an operand. Immediate mode contains the value in the instruction; register mode names a CPU register; direct mode gives the memory address; indirect mode uses a location or register that contains the effective address. These modes trade instruction size, flexibility and memory accesses. Be clear whether a number is an operand value or an address.

Simple example

If memory[200]=35, direct address 200 reads 35; immediate #200 uses the value 200 itself.

Exam takeawayTrace the address once and distinguish effective address from data.
09

Stack frames and subroutine return

A stack follows last-in, first-out order. A procedure call can place the return address and saved values on the stack; the called routine can use space for parameters or local data. On return, saved information is restored and execution continues at the return address. The stack pointer marks the current top. Nested calls work because each call has its own stack frame.

Simple example

If procedure A calls B and B calls C, C returns to B first; then B returns to A.

Exam takeawayTrace each push and pop in order and state where execution resumes.
10

Arithmetic-logic unit and control unit

The ALU performs arithmetic and logical operations on operands. The control unit decodes instructions and issues control signals that select registers, ALU functions and memory actions. Together with registers and buses, they form the processor's central datapath. When tracing an instruction, distinguish the unit that transforms a value from the unit that coordinates the sequence.

Simple example

For ADD R1,R2, control selects the ADD function and routes both register values to the ALU.

Exam takeawayTrace control signals and data movement as separate but coordinated jobs.
11

Instruction format and instruction length

An instruction format allocates bits to an opcode and operand fields. A fixed-length format simplifies fetching and decoding; a variable-length format can use space more flexibly but may require more complex boundaries. Field width limits how many opcodes, registers or address values can be represented. Use the format shown in the question rather than assuming a real CPU layout.

Simple example

A 3-bit register field can name at most eight registers because 2³=8.

Exam takeawayCalculate field capacity using 2^(number of bits) and label each field.
12

Memory read and write bus cycles

A memory read places an address on the address path, activates the read control signal and returns the selected contents on the data path. A write places both an address and the value to store, then activates write control. MAR and MDR commonly support these transfers. Timing may require the CPU to wait until memory signals that data is ready.

Simple example

To store 25 at address 300, put 300 in the address register, 25 on the data path and issue WRITE.

Exam takeawayFor each cycle, state address, data direction and read/write control.
13

Subroutine calls, return addresses and interrupts

A call transfers control to a procedure and preserves the return address so execution can resume afterward. A stack is a common place to save it. An interrupt is an event that temporarily transfers control to a handler; the processor preserves enough state to resume the interrupted program. Do not confuse a normal procedure call with an external event that requests attention.

Simple example

A timer interrupt saves the current program location, runs its handler and later returns to that location.

Exam takeawayShow what is saved, where control goes and how the original work resumes.
14

Hardwired and microprogrammed control

A hardwired control unit generates control signals through fixed logic, often making common operations fast but changes less flexible. A microprogrammed control unit uses stored microinstructions to sequence control signals; this can simplify complex instruction control but adds control-store access. Real designs can combine approaches. Compare implementation, flexibility and typical trade-offs rather than claiming one is always better.

Simple example

A complex instruction may be executed as a short sequence of micro-operations.

Exam takeawayExplain how each method produces control signals and give one trade-off.
15

Register-transfer operations

Register-transfer notation describes a data move or operation between registers during a clock step. An arrow may indicate transfer, while a control condition determines when it happens. For example, a register can load a value from a bus only when its load signal is enabled. This notation helps bridge high-level instruction steps and hardware control.

Simple example

R1←R2 means copy the contents of R2 into R1; R2 itself is unchanged.

Exam takeawayName the source, destination and control condition for a register transfer.
16

Branches and program-counter changes

After a normal instruction, the program counter advances to the next instruction. A branch changes that path: a conditional branch chooses a target only when its condition is true, while an unconditional jump always changes the PC. The target may be encoded as an address or computed relative to the current instruction.

Simple example

If zero flag Z=1, a branch-if-zero loads the target address into PC; otherwise execution continues sequentially.

Exam takeawayTrace both condition outcomes and state the new PC in each case.
17

Stack push, pop and stack pointer

PUSH places a value on the stack and updates the stack pointer; POP removes the top value and updates the pointer in the opposite direction. Exact increment/decrement direction depends on the machine convention. Because the stack is LIFO, the last value pushed is the first popped. Draw the stack before and after operations to avoid reversing order.

Simple example

Push 7, then push 3; pop returns 3 first, then 7.

Exam takeawayState the convention and show the top of stack after every operation.
18

Instruction set architecture and implementation

An instruction set architecture (ISA) defines the instructions, registers, data types and programmer-visible behavior of a processor. A microarchitecture is the internal design used to implement that ISA, such as pipelines, caches and execution units. Different processors can run the same ISA using different internal structures.

Simple example

Two processors may both execute the same assembly instruction while using different cache and pipeline designs.

Exam takeawaySeparate the programmer-visible contract from its hardware implementation.
19

Interrupt handling sequence

When an interrupt is accepted, the processor completes or safely suspends current work, saves the return context, identifies the interrupt source and branches to a handler. The handler services the event and restores enough state to resume the program. Priority and masking can determine which requests are handled first or temporarily delayed.

Simple example

A keyboard interrupt can save the current PC, read a key event in its handler and return to the paused program.

Exam takeawayShow save → handler → restore → resume, and mention priority if asked.

How the unit fits together

Connect the definitions, methods and applications before you start memorizing.

An instruction is a compact request that tells the processor what operation to perform and where its operands are. The instruction cycle is a controlled transfer of information: memory supplies an instruction, the control unit interprets it, the ALU or another unit performs work, and a result is stored. Registers reduce slow trips to main memory. Addressing modes alter the route to the operand, so the same arithmetic operation can read an immediate value, a register, or a memory location. Stack operations make nested calls manageable: every call can save a return address and local work, then restore the earlier context. These structures explain how a sequence of machine instructions can behave like a program with decisions, procedures and data.

Quick recap: teach these links back

01

Registers keep the work close

The program counter (PC) identifies the next instruction. The instruction register (IR) holds the instruction being handled. The memory address register (MAR) holds an address; the memory data register (MDR) carries data. An accumulator or general-purpose register can hold an operand or result. Registers are small and fast compared with main memory.

02

The instruction cycle is a repeatable loop

Fetch: use the PC to request the next instruction and place it in the IR. Decode: the control unit interprets the operation and finds operands. Execute: the ALU, memory or an I/O device performs the work. Write back: store the result and update the PC, either to the next instruction or a branch target. An interrupt can temporarily redirect execution.

03

Instructions find data in different ways

Immediate addressing puts a value inside the instruction; direct addressing gives a memory location; indirect addressing points to a location containing the real address; register addressing names a CPU register. RISC designs tend toward simpler, regular instructions; CISC designs may offer more complex instructions. These are tendencies, and modern CPUs can combine them. A stack is last-in, first-out storage, useful for return addresses and temporary values.

Follow every step

Try each task yourself first, then compare your working with the explanation.

EXAMPLE 1

Trace ADD R1,R2 through the CPU

TaskAssume the instruction adds R1 and R2 and writes the result to R1.

  1. The PC identifies the address of the instruction. Fetch it from memory into the IR and advance the PC.
  2. The control unit decodes ADD and identifies the two register operands.
  3. The ALU receives the values in R1 and R2 and adds them.
  4. Write the result back to R1. The CPU then uses the updated PC unless a branch or interrupt changes control.
Answer and reason

The answer should name PC, IR, control unit, ALU and write-back in the correct order.

EXAMPLE 2

Compare immediate and indirect addressing

TaskExplain how an instruction obtains its operand in each mode.

  1. Immediate: the operand value is part of the instruction itself, such as ADD #5,R1.
  2. Indirect: the instruction identifies a location that contains the real operand address; the CPU follows that pointer before reading the value.
  3. The indirect route may require an additional memory access compared with an immediate operand.
Answer and reason

Immediate contains the value; indirect contains or refers to an address that leads to the value.

QUESTION 1Describe the instruction cycle.+

The program counter identifies the next instruction. The control unit sends a memory-read request and the instruction is loaded into the instruction register; the program counter advances. The control unit decodes the instruction, identifies the operation and operands, then directs the required register, ALU or memory action. Finally, results are stored and control moves to the next instruction or to a branch target. An interrupt may temporarily redirect execution.

QUESTION 2Compare RISC and CISC at an introductory level.+

RISC traditionally emphasizes a smaller set of simpler instructions, regular instruction formats and efficient pipelining. CISC traditionally provides a larger set of more complex instructions, sometimes with variable formats and operations that combine several steps. The distinction is a design tendency rather than a strict rule: modern processors may use complex decoding internally while executing simpler micro-operations.

WORK IT THROUGH

Follow a simple instruction: ADD R1, R2.

  1. The PC supplies the instruction address; the CPU fetches it into the IR and advances the PC.
  2. The control unit decodes ADD and identifies R1 and R2. Their values go to the ALU.
  3. The ALU adds them, the result is written to the destination register, and execution continues at the next PC address.

WATCH OUT FOR

Easy mix-ups

  • The PC normally points to the next instruction address, not a data value.
  • Decode identifies the operation; execute performs it.
  • RISC and CISC are useful comparisons, not perfectly separate boxes for every modern CPU.
